# API NexaCRM

REST API доступен на всех тарифах по адресу https://api.nexacrm.example/v1. Это адрес вымышленного продукта; в рабочей среде организации используйте адрес, указанный в её панели интеграций. Запросы и ответы передаются как JSON по HTTPS. API позволяет читать и изменять доступные компании, контакты, сделки и задачи, а также получать список воронок. Версия v1 сохраняется в пути; несовместимые изменения публикуются в новой версии.

## Ключ доступа

Владелец и администратор создают персональные ключи в «Профиль → API-ключи». При создании задайте название, срок действия не более 365 дней и scopes: contacts.read, contacts.write, deals.read, deals.write или tasks.write. Полное значение ключа показывается только один раз. Передавайте его в заголовке Authorization как Bearer-токен. Не помещайте ключ в URL, клиентский JavaScript или общедоступный репозиторий.

Ключ действует с правами своего создателя. Scope ограничивает эти права дополнительно, а не расширяет их. Например, ключ администратора с contacts.read читает контакты, но не изменяет их; ключ отключённого пользователя недействителен. Экспорт CSV через интерфейс регулируется contacts.export и не выполняется обычным чтением API. Для полной выгрузки через API требуется читать записи постранично в пределах видимости и квоты.

## Запросы и ответы

Список контактов запрашивается методом GET /contacts?limit=100&cursor=..., создание — POST /contacts, изменение — PATCH /contacts/{id}. Для сделок используются аналогичные пути /deals. Максимальный размер страницы — 100 записей. Ответ списка содержит items и next_cursor; пустой next_cursor означает конец выборки. Сортировка по умолчанию идёт по дате изменения и ID, поэтому сохраняйте курсор до окончания обхода.

Для POST можно передать заголовок Idempotency-Key с уникальным значением до 128 символов. Повтор того же запроса с тем же ключом в течение 24 часов возвращает исходный результат; ключ с другим телом вызывает 409. Это особенно полезно при сетевом тайм-ауте. Времена передаются в ISO 8601 с часовым поясом. API не создаёт записи сверх тарифного лимита контактов.

Ошибки имеют JSON-поля code, message и request_id. Сохраняйте request_id при обращении в поддержку, но не присылайте токен. Ответ 401/API-401 означает недействительный или отозванный ключ, 403/API-403 — нехватку scope или прав на запись, 404 — отсутствие доступной записи, 422 — ошибку в полях.

## Квоты и повтор запросов

| Тариф | Запросов за скользящие 30 дней | Запросов в минуту на пространство |
| --- | ---: | ---: |
| Старт | 10 000 | 60 |
| Команда | 60 000 | 300 |
| Бизнес | 600 000 | 1 000 |

Все ключи одного пространства делят квоты. Неудачные запросы, дошедшие до API, учитываются; запросы, отклонённые из-за превышения квоты, не учитываются повторно. При 429/API-429 соблюдайте заголовок Retry-After. Для фоновой синхронизации используйте очередь и экспоненциальную задержку с небольшим случайным разбросом. Исходящие webhooks не расходуют API-квоту. Статистика использования доступна владельцу и администратору в «Настройки → Использование».
