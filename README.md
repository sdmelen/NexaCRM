# NexaCRM Support AI

Локальный демонстрационный RAG-помощник по 15 Markdown-документам из `source/`. Сейчас завершена **итерация 5**: веб-чат отвечает по найденным фрагментам, показывает проверенные источники, ведёт диалог до 15 вопросов и позволяет сохранять заявки в локальной SQLite. План разработки — в [ITERATION_PLAN.md](ITERATION_PLAN.md), результат этапа — в [ITERATION_5_REPORT.md](ITERATION_5_REPORT.md).

Поиск использует семантическую выдачу Qdrant, BM25 и RRF. Заявки сохраняются только после подтверждения; текущая переписка хранится в Streamlit-сессии.

## Установка и индексация в Windows PowerShell

Нужен Python 3.12. Выполните команды из папки проекта:

~~~powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
~~~

Добавьте `OPENAI_API_KEY` в `.env`. Команда выше сохраняет существующий файл `.env`. Проверьте, что исходные документы находятся в `source/`, затем запустите:

~~~powershell
.\.venv\Scripts\python.exe ingest.py --dry-run
.\.venv\Scripts\python.exe ingest.py
~~~

`--dry-run` проверяет разбиение без API-запросов и записи в Qdrant. Обычная команда запрашивает embeddings через OpenAI и создаёт индекс в `data/qdrant/`; манифест проверки находится в `data/index_manifest.json`. На текущем корпусе ожидаются **15 документов, 68 фрагментов и 68 сохранённых embeddings** размерности 1536 при настройках по умолчанию. При изменении файлов или параметров chunking эти числа могут отличаться. Повторная индексация создаёт новую коллекцию, проверяет её и только затем переключает рабочий индекс; при сбое старый индекс сохраняется.

Во время ручной индексации закройте запущенное веб-приложение: локальный Qdrant использует блокировку каталога. Обычный запуск веб-приложения не вызывает Embeddings API и не перестраивает индекс.

## Запуск приложения

~~~powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1
~~~

Откройте `http://127.0.0.1:8501`. На странице «AI-оператор» должны отображаться 15 документов, добавленный API-ключ и готовый индекс из 68 фрагментов. Задайте вопрос, например «Сколько действует ссылка приглашения коллеги?». Под ответом раскройте «Источники»: там показаны документ, раздел, файл, номер и ID фрагмента, YAML-метаданные и его текст. На вопрос вне документации оператор сообщает о недостатке сведений и предлагает заявку.

Кнопка «Создать заявку» доступна всегда; после ответа без достаточных сведений появляется отдельная кнопка заявки. Форма предлагает тему и описание, показывает предупреждение о чувствительных данных и сохраняет обращение только после нажатия «Подтвердить и сохранить заявку». Список и содержимое доступны на странице «Заявки» даже после перезапуска приложения; файл базы — `data/tickets.sqlite3`. Для нового чата нажмите «Новый диалог»: текущая история в браузере будет очищена, сохранённые заявки останутся.

Счётчик показывает число успешно обработанных вопросов из 15. На 15-й вопрос оператор отвечает, затем поле ввода блокируется и открывается черновик заявки с историей переписки. Если ответ не получен из-за ошибки, вопрос можно повторить без расходования лимита. Длина вопроса ограничена `MAX_QUESTION_CHARS` (по умолчанию 4000 символов), длина ответа — `MAX_ANSWER_CHARS` (2500 символов). Пределы задаются в `.env`; история передаётся целиком без скользящего окна. При стандартных настройках верхняя граница текста 15 пар реплик составляет 97 500 символов, без учёта фрагментов документации и служебных инструкций. Если порт занят, добавьте `--server.port 8502`. Остановка — `Ctrl+C` в терминале.

## Проверка

~~~powershell
.\.venv\Scripts\python.exe -m nexacrm.eval_cases
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe search.py "Сколько действует ссылка приглашения коллеги?"
.\.venv\Scripts\python.exe evaluate_retrieval.py
.\.venv\Scripts\python.exe ask.py "Сколько действует ссылка приглашения коллеги?"
.\.venv\Scripts\python.exe ask.py "Как включить встроенный видеоредактор в NexaCRM?"
~~~

Первая команда проверяет фиксированный набор из 33 контрольных сценариев и подтверждающие места в документации. Тесты проверяют чанкинг, YAML-метаданные, Qdrant, токенизацию, RRF, преобразование уточняющего вопроса с fallback и страницы приложения. `search.py` показывает top-8 каждого поиска, общий рейтинг и пять выбранных чанков. Для полного текста и метаданных используйте `--json`. Для уточняющего вопроса можно передать `--history-file путь-к-json` с массивом сообщений вида `[{"role":"user","content":"..."},{"role":"assistant","content":"..."}]`.

`evaluate_retrieval.py` прогоняет контрольный набор и записывает исходный и поисковый запросы, обе выдачи, оценки, ранги, текст и метаданные в `data/retrieval_eval.json`. Код завершения 2 означает, что доля случаев с ожидаемыми разделами в выбранном контексте ниже 90%. На текущем корпусе результат — **27/28 по разделам и 26/28 по точным цитатам**. `ask.py` показывает ответ с источниками; `--json` выводит также полную поисковую диагностику. Для уточняющего вопроса передайте `--history-file` с тем же форматом истории, что и для `search.py`.

Полная проверка генерации выполняется отдельно:

~~~powershell
.\.venv\Scripts\python.exe evaluate_answers.py
~~~

Она делает вызовы OpenAI по 33 сценариям и сохраняет ответы, источники и выдачу в `data/answer_eval.json`. Ручная оценка из `tests/fixtures/answer_reviews_iteration4.json` применяется только к **точно совпадающей версии ответа и текстов источников**; изменившийся ответ нужно проверить снова. К уже сохранённому прогону оценку можно применить без вызовов API: `.\.venv\Scripts\python.exe evaluate_answers.py --apply-review`. На проверенном прогоне ожидаемые факты есть в **27/28** случаях с эталонными источниками; все существенные фактические утверждения проверены по указанным фрагментам, а четыре вопроса без ответа получили отказ. `data/` и `.env` исключены из Git.

## Метаданные фрагментов

Вместе с текстом и вектором каждого фрагмента Qdrant хранит `chunk_id`, `source_file`, `document_name`, `document_title`, `section_title`, `section_path`, `chunk_index` и `front_matter`. Название документа берётся из YAML `title`, затем из H1, затем из имени файла. YAML сохраняется отдельно и не может подменить обязательные поля. Источники под ответом строятся из этих метаданных Qdrant, после проверки, что названные моделью ID были переданы ей в контексте. Наличие источника само по себе не доказывает достоверность текста; для контрольного набора каждое существенное утверждение проверено отдельно.

При индексации текст документации передаётся в OpenAI Embeddings API. Во время поиска туда передаётся поисковый запрос; история уточняющего вопроса передаётся модели для его преобразования. Для генерации ответа в OpenAI передаются вопрос, история и до пяти выбранных фрагментов с метаданными. Эти вызовы могут повлечь расходы по тарифу API. Не вводите в демонстрационные вопросы и заявки реальные персональные данные, пароли или ключи. Приложение предназначено для запуска на `127.0.0.1`, а не для публичного размещения.
